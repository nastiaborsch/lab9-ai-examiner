# Лабораторна робота №9: AI Examiner Agent (NLP)

## Суть проєкту

Вебзастосунок для усного іспиту з NLP, де Llama 3.3 70B через Groq API **справді викликає** локальні Python-інструменти, а не лише імітує агента. Агент ставить запитання за 2–3 випадковими темами, може уточнювати відповіді, оцінює всі репліки студента і завершує іспит підсумковою оцінкою 0–10. Дані зберігаються в `data/exams/<id>.json`.

## Швидкий запуск у PyCharm / терміналі

1. Відкрийте папку `Lab9_AI_Examiner` як проєкт у PyCharm.
2. Виберіть Python 3.10 або новіший. Створіть `.venv` (PyCharm може запропонувати автоматично).
3. У терміналі проєкту виконайте:

   ```bash
   python -m pip install -r requirements.txt
   python app.py
   ```
4. Відкрийте **http://127.0.0.1:7860** у браузері.
5. На [console.groq.com/keys](https://console.groq.com/keys) створіть Groq API key (доступ до моделі та ліміти визначаються вашим акаунтом). Вставте ключ у поле вебінтерфейсу.
6. Введіть демонстраційні дані:
   - Ім’я: `Тестовий Студент`
   - Email: `test.student@example.com`
7. Натисніть **«Почати іспит»**, дайте відповіді на питання, за потреби введіть `не знаю`. Продовжуйте до фінальної оцінки.

**Важливо:** потрібен інтернет та робочий Groq API key. Без ключа реальні LLM-виклики не працюють. Нічого не потрібно вставляти в код.

## Структура

- `app.py` — Gradio-інтерфейс.
- `agent.py` — LLM-агент, function calling, генерація питань, перевірка та відгуки.
- `exam_tools.py` — точні функції `start_exam(email, name)`, `get_next_topic()` і `end_exam(email, score, history)`.
- `data/students.json` — список зареєстрованих студентів (демодані, можна змінити).
- `data/exams/` — початкові й фінальні JSON-записи кожного іспиту (створюються автоматично).
- `tests/` — автоматичні тести без зовнішнього API.
- `SUBMISSION.md` — готовий опис для здачі + місця для посилань.

## Як працює агент

1. Форма запитує ім’я, email і Groq API key (ключ не зберігається в файлах).
2. Модель через **tool calling** викликає `start_exam`; Python перевіряє студента за `data/students.json`, фіксує початок і повертає випадкові 2–3 теми.
3. Модель викликає `get_next_topic`. Генерує перше запитання цієї теми.
4. Студент відповідає; LLM оцінює *всю розмову про тему* на шкалі 0–10. Якщо відповідь неповна, питає уточнення. Тема завершується, коли якість достатня (від 7.5), студент не знає, рівень знань вже зрозумілий, або зроблено 3 ходи.
5. Для наступної теми знову відбувається tool call `get_next_topic`.
6. Після останньої теми модель формулює підсумковий відгук. Підсумкова оцінка — середнє балів по темах. Модель викликає `end_exam`, а Python додає перевірену повну історію та зберігає результат.

### Дані, які зберігаються

`exam_id`, `email`, `name`, `topics`, `started_at`, `finished_at`, `status`, `topic_scores`, `topic_feedback`, `score`, `history`. Повідомлення `history` мають формат `{"role":"system|user|tool_call", "content":"...", "datetime":"2026-..."}` із часовими мітками. Повідомлення бота позначено `system`, оскільки **саме такий набір ролей визначений методичкою**. У Gradio вони відображаються як `assistant`.

Для ізоляції одночасних сесій використано `ContextVar`, для збереження — окремі файли з атомарним перезаписом. При неправильних даних студента `start_exam` повертає помилку, після чого форма просить перевірити ім’я та email.

## Тестування

Запуск у терміналі (не потрібні Groq API key та Gradio):

```bash
python -m unittest discover -s tests -v
```

Тести перевіряють інструменти, реєстрацію / відмову, випадкові теми, перебіг іспиту, оцінку, збереження історії, виклики всіх трьох tool-функцій та відсутність API ключа у файлі результату. Модульне тестування **не означає**, що реальний Groq API вже перевірений — виконайте пробний повний іспит з власним ключем.

## Можливе розміщення на Hugging Face Spaces

Можна створити новий Gradio Space на https://huggingface.co/spaces, завантажити сюди `app.py`, `agent.py`, `exam_tools.py`, `requirements.txt`, `data/students.json` і файл `README.md` (для Spaces додайте YAML `sdk: gradio` та `app_file: app.py`). У `app.py` вже передбачено автоматичний перехід на `0.0.0.0` в оточенні Spaces, тому вручну змінювати код для деплою не потрібно. **Зверніть увагу:** локальні JSON-файли на безкоштовному Space можуть бути непостійними після перезапуску; для довготривалого збереження потрібен persistent storage. Не публікуйте файли з реальними результатами/електронними адресами та не вставляйте секрети в репозиторій.

## Обмеження

Оцінювання є приблизним і здійснюється LLM; це демонстраційний навчальний проєкт, а не формальний екзаменаційний сервіс. При недоступності Groq API або перевищенні лімітів потрібна повторна спроба; Groq API key не включено в репозиторій.
